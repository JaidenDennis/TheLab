## Getting the code onto another machine

**Preferred: push to the remote.** Nothing has been pushed yet — there is no
remote configured, and this machine has no stored GitHub credentials. From the
repo root:

```
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

Authentication will be needed. Either install the GitHub CLI
(`winget install GitHub.cli`, then `gh auth login`), or use a personal access
token as the password when prompted.

**Fallback with no network or no credentials:** `nq-agent-full.bundle` sits one
directory up (`Desktop/Auto Trading/`). It is 0.25 MB and contains the complete
43-commit history. Copy it to the new machine and:

```
git clone nq-agent-full.bundle nq-agent
cd nq-agent
git remote remove origin        # points at the bundle file, not a real remote
```

`nq-agent-git-history.bundle` inside the repo is the ORIGINAL scaffolding
bundle from before this work. It is stale and redundant — its history is a
subset of what is now in `.git`. Delete it whenever.

## Setting up on the new machine

```
git config core.autocrlf false          # see the warning below -- do this FIRST
uv venv --python 3.12
uv pip install -e ".[dev]"              # add ",live" for databento + aiohttp
uv run pytest -q                        # expect 385 passing
```

If `uv` is not installed: `python -m pip install uv`. Note it may land in a
Scripts directory that is not on PATH — `python -m uv` works regardless.

**Windows line endings.** `core.autocrlf` defaults to `true` on Windows, which
rewrites every file to CRLF on checkout, including the 5,041-line tick fixture.
Set it to `false` in the repo before doing anything else. This bit us once
already this session.

## Where things stand

Steps 1–10 of the original build sequence were the scaffolding (done before
this session). This session added, in order:

1. Two Windows-only defects fixed — the journal was silently losing records
   under concurrency, and sqlite connections were never explicitly closed.
2. **Phase A** — crash-safe teardown, `Executor.close()`, wiring-time
   validation, and the `FeedBinding` seam so a live feed no longer means
   editing `run_from_config`.

   a backtester that runs the real engine and reports P&L off the journal;
   `OpeningRangeBreakout` as a reference strategy.

5. **Phase D** — tri-state `OrderOutcome`, `WebhookExecutor`.
6. **Phase E** — money-aware risk limits, `docs/RUNBOOK.md`.
7. Position reconciliation against broker truth.
8. Unrealised P&L risk, with a protective flatten on breach.

Read `docs/RUNBOOK.md` before running anything against an account. Its go-live

## A note on how this was verified

Every safety-critical change was mutation-tested: break the behaviour on
purpose, confirm a test goes red. That found three tests this session that
were passing for the wrong reason — including one where a drawdown test would
have passed whether or not the high-water mark logic existed at all. If you
add to the risk layer, do the same. The scratch scripts are gone, but the
pattern is: patch the source, run the suite, restore, assert it went red.
